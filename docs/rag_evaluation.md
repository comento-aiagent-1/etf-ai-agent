# FAQ RAG 성능 검증 및 최종 설정

## 평가 목적

FAQ 의미 검색에 사용할 임베딩 모델, 검색 결과 수(`top-k`), 유사도 임계값과 청크 설정을 실제 질문으로 비교했습니다. 평가 코드는 `eval_faq_rag.py`, 정답 데이터는 `data/evaluation/faq_rag_questions.json`에 있습니다.

## 평가 데이터

- FAQ 원문: 75개
- 의미가 같은 자연어 변형 질문: 50개
- FAQ 검색에서 제외해야 하는 시세·뉴스·공시·추천·비교 질문: 10개
- 중복되거나 의미가 같은 FAQ는 복수 정답으로 인정
- 비교 모델: `text-embedding-3-small`, `text-embedding-3-large`
- 비교 차원: 모두 1536차원으로 통일

## 모델 비교 결과

| 모델 | hit@1 | hit@3 | hit@5 | MRR@3 | 임계값 0.55 균형정확도 | 비FAQ 오탐률 |
|---|---:|---:|---:|---:|---:|---:|
| text-embedding-3-small | 86% | 90% | 92% | 88% | 75% | 20% |
| text-embedding-3-large | **90%** | **96%** | **98%** | **93%** | **94%** | **0%** |

실행 시간은 API 네트워크 상태에 따라 달라지는 단일 측정값이므로 모델 선정 기준으로 사용하지 않았습니다. 이번 실행에서는 small 2.23초, large 1.93초였으며 장기 평균 지연시간을 의미하지 않습니다.

## 최종 설정

| 항목 | 최종값 | 선정 근거 |
|---|---|---|
| 임베딩 모델 | `text-embedding-3-large` | 같은 1536차원에서 hit@1·hit@3·비FAQ 차단 성능이 모두 우수 |
| 임베딩 차원 | 1536 | 기존 pgvector 구조·저장공간·HNSW 인덱스와 호환하면서 large의 검색 성능 확보 |
| top-k | 3 | hit@1 90%에서 hit@3 96%로 6%p 개선되고, top-5의 추가 개선은 2%p에 그침 |
| 최소 유사도 | 0.55 | 임계값 적용 hit@3 88%, 비FAQ 10개 거부율 100%, 균형정확도 94% |
| chunk size | 1000자 | 현재 FAQ 임베딩 문서 최대 484자로 모든 FAQ가 한 청크이므로 더 작은 청크는 정보만 분리함 |
| chunk overlap | 100자 | 향후 1000자를 넘는 문서가 추가될 때 문맥 단절을 줄이기 위해 기존 설정 유지 |

## 실제 pgvector 통합 검증

선정한 모델과 임계값으로 로컬 PostgreSQL의 75개 FAQ 임베딩을 재생성한 뒤, 같은 평가 질문 60개를 실제 `search_faq_vectors` 경로로 실행했습니다.

- 임계값 적용 hit@1: 82%
- 임계값 적용 hit@3: 88%
- 비FAQ 질문 거부율: 100%
- OpenAI 임베딩·PostgreSQL·pgvector 실연동 테스트: 통과

임계값을 적용하지 않은 순수 순위 성능(hit@3 96%)보다 실제 검색 성공률이 낮은 것은, 점수가 0.55 미만인 질문을 의도적으로 제외했기 때문입니다. 금융 서비스에서는 관련성이 낮은 FAQ를 답변 근거로 넣는 것보다 검색 결과 없음으로 처리하는 편이 안전하다고 판단했습니다.

추가로 URL·날짜를 제외하고 `질문·키워드·답변`만 임베딩하는 표현도 비교했습니다. 순수 hit@3는 98%로 높아졌지만 임계값 0.55의 균형정확도는 93%로 현재 전체 행 표현의 94%보다 낮아, 이번 버전에는 적용하지 않았습니다.

## 발표용 한 장 요약

**왜 이 설정을 선택했는가?**

75개 FAQ에 대해 자연어 변형 50개와 검색 제외 질문 10개를 평가했습니다. `text-embedding-3-large(1536차원)`는 `small`보다 임계값 적용 전 hit@3가 90%에서 96%로 높았고, 임계값 0.55를 적용한 실제 검색 조건에서도 hit@3 88%와 비FAQ 거부율 100%를 기록했습니다. `top-k=3`은 top-1보다 정답 포함률이 6%p 높으면서 top-5 대비 결과 수를 줄일 수 있어 선택했습니다. 모든 FAQ 문서가 484자 이하라 현재는 문서당 한 청크이며, 따라서 청크 크기는 기존 1000자와 100자 겹침을 유지했습니다.

## 남은 검증 과제

- 평가 질문을 팀원이 교차 검토해 정답 FAQ 라벨의 주관성 확인
- 실제 사용자 질문 로그를 익명화해 오답·미검색 사례를 평가셋에 추가
- Azure 배포 환경에 `FAQ_MIN_SIMILARITY=0.55`를 반영하고 배포 DB의 FAQ 임베딩을 동일 설정으로 재생성
